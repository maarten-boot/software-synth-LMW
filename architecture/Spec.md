# Spec — software-synth-LMW

Items marked (?) await user confirmation.

## S1 Purpose
S1.1 A polyphonic software synthesizer, inspired by AlsaModularSynth (modules + patch cables).
S1.2 Semi-modular: a default signal path is prewired ("normalled"); inserting a patch cable into an input overrides its default connection. Own design, inspired by the ARP 2600 concept (not a replica).

## S2 Platforms & language
S2.1 Runs on Linux, macOS and Windows from one codebase. Linux targets: Ubuntu 24.04 LTS and newer, and the latest Fedora release (currently 45). Linux binaries are built on the oldest supported distro so they also run on newer ones.
S2.2 C++20, CMake, JUCE 9.
S2.3 CI and other external build steps (GitHub Actions `uses:` etc.) are pinned to a full commit SHA with the version as a comment, using the latest workable version; any exception is documented with its reason. Exceptions: GitHub runner images cannot be pinned by hash, so they are fixed to version labels — ubuntu-24.04 (oldest supported target, S2.1), macos-26 and windows-2025 (Visual Studio 2026), the images -latest pointed to on 2026-11-09; the Fedora container is pinned by digest, but the packages it installs with dnf come from the live Fedora 45 repositories (distribution packages are not pinnable per build). Exception: NSIS for the Windows installer (S9.5) comes from Chocolatey at a pinned version (3.13.0, the step checks what makensis reports); it is not an action, so it cannot be pinned by hash.
S2.4 Build dependencies (user 2026-11-21): scripts/prepare.sh lists the packages a build needs and which are missing (exit 1 when any is), and with --install installs them (apt on Ubuntu/Debian, dnf on Fedora, brew on macOS; sudo unless root); --optional adds Xvfb, xdotool, ImageMagick and podman; on Windows it names what to install. It holds the one package list: CI's Linux jobs and scripts/build-ubuntu24.sh install through it (Fedora installs only git, tar and gzip before the checkout). Package names that exist on Ubuntu 24.04 and 26.04 alike (libfontconfig-dev, libgl-dev; the older libfontconfig1-dev and libgl1-mesa-dev are transitional names, absent on a 26.04 that has the new ones).

## S3 Audio & MIDI
S3.1 Audio output via JUCE audio device layer (standalone) / host (plugin).
S3.2 Input: MIDI keyboard; computer keyboard as fallback in standalone. Computer-keyboard notes (keys a w s e d f t g y h u j k o l p ;, starting at C4 = MIDI 60) work whichever control has focus, except while typing into a value box; after a popup menu (presets, sockets, panel title) closes, focus returns to what had it, so the keys keep playing (fixed 2026-11-21: they were silent until the on-screen keyboard was clicked). Note names are scientific pitch: C4 = MIDI 60 = 261.6 Hz (A4 = 440 Hz), C0 = 16.35 Hz, MIDI 0 = C-1 (8.18 Hz). The on-screen keyboard (user 2026-11-13) shows the piano range A0–C8 (MIDI 21–108, 88 keys, 27.5 Hz–4186 Hz), labelled C1 … C8, its keys widened to fill the window (16 px minimum, then it scrolls; since Phase 24b at their normal width at the right of a wider window, S6.16); a MIDI controller still plays all 128 notes. Before 2026-11-13 the keys were labelled with JUCE's default (MIDI 60 = "C3", down to "C-2") and the "a" key played MIDI 72 (C5).
S3.3 Sustain pedal (CC64): while down, released keys keep sounding; pedal up releases them. Re-striking a sustained note retriggers it (no doubling).
S3.4 Pitch bend: applies to all sounding and new voices; range ±2 semitones (fixed for now; may become a parameter).
S3.5 Mod wheel (CC1): adds vibrato — the FM depth of each VCO becomes vcoN.fm + wheel × 1 semitone (the LFO always reaches vcoN.fm; changed 2026-11-08 so FM also works without a MIDI controller).

## S4 Polyphony
S4.1 Voice count configurable at runtime, range 1–32.
S4.2 When all voices are busy, a new note steals the oldest voice, preferring voices already in release over held ones.
S4.3 A note-on for a note that is already sounding retriggers that voice (no doubling).
S4.4 Stealing/retriggering keeps phase and envelope level continuous (no click).
S4.5 Lowering the voice count releases the excess voices (they ring out); parameter id voice.count, default 8.
S4.6 The summed output passes a soft limiter: unchanged below -6 dBFS, smooth (tanh) knee above, never above -0.04 dBFS — no hard clipping with many voices.

## S5 Modules (initial set)
S5.1 VCO, VCF, VCA, ADSR, LFO, Mixer, Noise, MIDI-in, Audio-out. VCF: 24 dB/oct lowpass ladder with resonance. LFO: two shared (global) LFOs for all voices (S5.12; one until Phase 9).
S5.2 Default normalled patch (confirmed 2026-11-07): MIDI→VCO pitch; VCO→Mixer→VCF→VCA→Out; Noise→Mixer (level 0); ENV1→VCA; ENV2→VCF cutoff; LFO→VCO pitch with depth set by the mod wheel (0 by default). Since then: LFO 1 → vcoN.fm (S3.5, S5.10), LFO 2 → vca.mod for tremolo (S5.12), VCF 2 after VCF 1 (S5.11); the current list is S5.3.
S5.3 Ports. Outputs: keys.pitch, keys.gate, keys.vel (S5.8), vco1.out, vco2.out, vco3.out (S5.10), noise.out, noise.rand (S5.15), lfo1.out, lfo2.out (S5.12), env1.out, env2.out, mix.out, vcf1.out, vcf2.out (S5.11), formant.out (S5.16), vca.out. Inputs, with their normalled source (written source → input): keys.pitch → vco1.pitch, vco2.pitch, vco3.pitch; lfo1.out → vco1.fm, vco2.fm, vco3.fm; vco1.pm, vco2.pm, vco3.pm (none, S5.20); keys.gate → env1.gate; keys.gate → env2.gate; vco1.out → mix.in1; vco2.out → mix.in2; vco3.out → mix.in3; noise.out → mix.in4; mix.out → vcf1.in; env2.out → vcf1.cutoff; vcf1.res (no normalled source, S5.13); vcf1.out → vcf2.in; env2.out → vcf2.cutoff; vcf2.res (none); vcf2.out → formant.in; formant.vowel (none); formant.out → vca.in (S5.16; before: vcf2.out → vca.in); env1.out → vca.cv; lfo2.out → vca.mod (S5.12); keys.vel → vca.vel (S5.22, since Phase 26); vca.out → out.in; lfo1.rate, lfo2.rate (none, S5.19).
S5.4 Cables (pins since Phase 10, S5.14). A cable connects one output to one input at a level 0–100 % (a cable drawn on the Synth tab is 100 %, levels are set in the matrix S6.8 or over 9P); an output may feed several inputs; an input takes up to 4 cables, which are summed (level × output each). Cables replace the input's normalled source (they do not add to it); removing the last one restores it. Input amounts (vcoN.fm, mixer levels, vcfN.env) still apply to the patched signal. A cable from a module computed later in the same sample (feedback) reads that output's previous sample. Cable changes reach the audio thread through a lock-free queue (S10.2). All cable changes are made on the message thread (the queue has a single producer): from the GUI, from 9P (S10.12), and from a restored state — a host restoring state on another thread gets its cables a moment later.
S5.5 Signal levels: audio ±1; envelopes 0..1; LFO ±1; noise: white uniform ±1, pink and brown about ±1 (S5.15); noise.rand ±1. vcoN.fm input: 1.0 in = (vcoN.fm + mod wheel × 1) semitones. vcoN.pitch input: 1.0 = one octave (0 = C4). vcfN.cutoff input: 1.0 in = vcfN.env octaves. Gates: on above 0.5. VCA gain = vca.initial + vca.cv, clamped to 0..1, times the tremolo factor 1 − vca.tremolo × (1 − vca.mod)/2 (vca.mod clamped to ±1; S5.12), times the velocity factor 1 − vca.velocity + vca.velocity × vca.vel clamped to 0..1 (S5.22, since Phase 26; before: times the note velocity). out.in: per-voice signals are summed; a global source (lfo1, lfo2, noise, noise.rand) is output once.
S5.6 Shared (global) modules: LFO 1, LFO 2, Noise and its sample & hold random (S5.15). Per voice: KEYS outputs, VCO 1–3, ENV1, ENV2, Mixer, VCF 1, VCF 2, FORMANT (S5.16), VCA. The shared LFOs' rate inputs take per-voice sources from the newest note (S5.19). When the sound no longer ends with ENV1 (out.in or vca.cv patched, vca.initial > 0, or env1.gate fed by something other than keys.gate, S5.8), voices that have played keep running after release (drone), as on a modular.
S5.7 VCF: 24 dB/oct lowpass ladder (zero-delay-feedback, 4 one-pole stages, tanh-limited feedback), resonance 0..1 (self-oscillates near 1); cutoff 20 Hz–18 kHz, smoothed 20 ms in the log domain.
S5.8 KEYS module (Phase 4 step 2b). On-screen keyboard, computer keys and MIDI are merged before voice allocation, so they form one per-voice source: the KEYS panel (formerly POLY: Voices fader plus sockets), first in the bottom panel row next to the envelopes (row 3 since S5.10), 2 columns wide. Outputs, per voice: keys.pitch (1.0 = one octave, 0 = C4 / MIDI 60, pitch bend included), keys.gate (1 while the key is held or sustained by the pedal, else 0), keys.vel (note-on velocity 0..1). New inputs with their normalled source: keys.pitch → vcoN.pitch (each VCO, S5.10); keys.gate → env1.gate; keys.gate → env2.gate. vcoN.pitch sets that VCO's pitch (C4 + 12 × input semitones, plus its Octave and Tune); vcoN.fm still adds on top. An envelope gated by keys.gate (normalled or by cable) follows the key events, so a repeated note retriggers it; gated by any other signal it starts on a rising edge (crossing 0.5 upward) and releases on a falling one; when its gate returns to the keys while the key is up, it is released. A voice whose env1.gate comes from something other than keys.gate keeps running after its key is released (drone rule S5.6); vcoN.pitch does not need this, as the sound still ends with ENV1. The default patch produces bit-identical output to before. The VCA keeps multiplying by velocity. A separate MIDI module is out of scope until several MIDI inputs/channels exist.
S5.9 VCF modes (Phase 4b a). Each VCF has Slope 24 / 12 / 6 dB per octave and Type Low / High / Band / Notch (parameters vcf.slope, vcf.type; choice boxes stacked in a fourth VCF column), made by mixing the ladder's input after feedback y0 and its four stage outputs y1..y4 (as in the Oberheim Xpander), so cutoff, resonance and self-oscillation behave alike in every mode: LP = y1 / y2 / y4; HP = y0−y1 / y0−2y1+y2 / y0−4y1+6y2−4y3+y4; BP = 2(y1−y2) / 4(y2−2y3+y4) (gain 1 at the cutoff); Notch = 1 − BP (y0−2y1+2y2 / y0−4y2+8y3−4y4, zero at the cutoff). Bandpass and notch have no 6 dB form: 6 dB acts as 12 dB (stated in the Slope hover text). Default 24 dB lowpass: exactly the original signal path (default sound bit-identical). A mode change crossfades the mix over 20 ms (no click).
S5.10 VCO 1–3 (Phase 4b b). Three VCOs per voice, each with FM depth, Tune (−7..+7 semitones, 0.01 st steps), Wave and Octave (−2..+2, choice "Oct" stacked under Wave); sockets vcoN.fm, vcoN.pitch (inputs, under the FM and Tune faders) and vcoN.out. Normalled: keys.pitch → vcoN.pitch; lfo1.out (then lfo.out) → vcoN.fm (the mod wheel adds to every VCO's FM depth); vco1.out → mix.in1; vco2.out → mix.in2; vco3.out → mix.in3; noise.out → mix.in4. Mixer levels VCO 1 (default 100 %), VCO 2, VCO 3 (0 %), Noise (0 %). A VCO is only computed when something uses it (a mixer input with level above 0, or any other input), so VCO 2 and 3 cost nothing by default. Names changed: vco.* → vco1.*, mix.vco → mix.vco1, the old noise input mix.in2 → mix.in4; the saved state gets "stateVersion" 2, and a state without it is translated on load (parameter IDs and cable names, StateMigration.h). The default sound is bit-identical. Default layout: three rows — VCO 1 | VCO 2 | VCO 3 | LFO | OUT; MIXER | VCF | VCA; KEYS | ENV 1 | ENV 2 (row height reduced so it fits: window 1026×884, compact 762×678).
S5.11 VCF 2 (Phase 4b c). A second VCF with the same controls (Cutoff, Reso, Env 2, Slope, Type) and sockets (In, Cut, Out), in series: vcf1.out → vcf2.in, vcf2.out → vca.in, env2.out → vcf2.cutoff. Ports and parameters vcf.* became vcf1.* (state version 3; older states translated on load, StateMigration.h). VCF 2 is always computed (its state stays current); it is open — its output exactly its input — while it is a 24 dB lowpass without resonance whose modulated cutoff is at the maximum (the default; positive Env 2 modulation keeps it open). Entering or leaving that state crossfades over 20 ms, after the 20 ms cutoff glide. The default sound is bit-identical. Layout: row 2 MIXER | VCF 1 | VCF 2; VCA moved to the end of row 3.
S5.12 LFO 2 and tremolo (Phase 9a, 2026-11-12). Two shared LFOs with the same controls (Rate 0.05–20 Hz, Wave Sine/Triangle/Saw/Square): LFO 1 is the former LFO (vibrato, normalled to vco1.fm, vco2.fm, vco3.fm, depth = the FM faders + mod wheel); LFO 2 [4 Hz, Sine] is normalled to a new VCA input vca.mod (tremolo). The VCA gets a Tremolo fader (vca.tremolo 0–1 [0]) above the Mod socket: the gain is multiplied by 1 − depth × (1 − vca.mod)/2, so with mod +1 it is unchanged and with mod −1 it drops by the depth; depth 0 leaves the gain exactly as it was. Like any input, vca.mod takes a cable instead (e.g. keys.vel or env2.out). Names changed: lfo.out → lfo1.out, lfo.rate → lfo1.rate, lfo.wave → lfo1.wave (state version 4; older states and patch files translated on load, StateMigration.h). The default sound is bit-identical. Layout: row 1 VCO 1 | VCO 2 | VCO 3 | LFO 1 | LFO 2; OUT moved to the end of row 3 (KEYS | ENV 1 | ENV 2 | VCA | OUT); the widest row has 13 columns. A saved panel layout from before is replaced by the default (it lists one panel fewer).
S5.13 VCF key tracking and resonance input (Phase 9c, 2026-11-12). Each VCF gets a Key fader (vcfN.key 0–100 % [0], between Env 2 and Slope/Type): the cutoff moves Key × (keys.pitch) octaves, i.e. at 100 % one octave per octave of the keys (pitch bend included), unchanged at C4; 0 % = the same cutoff for every note. And a Res input socket (vcfN.res, under the Reso fader) whose signal is added to the Reso fader, clamped to 0..1 — no amount fader (user decision); e.g. keys.vel → vcf1.res makes harder notes resonate more. vcfN.res is the first input without a normalled source: unpatched it reads 0 (adds nothing); hover texts say "not connected", 9P /ports lists its source as "none". Both are only computed when used, so the default sound is bit-identical. VCF panels are 5 columns wide: the widest row has 14 columns, window 1166×884. No state version change: older states simply get Key 0 and no Res cable.
S5.14 Pin matrix model (Phase 10a, 2026-11-12). Every input has up to 4 pins (output, level 0 < level ≤ 1; since Phase 25a 0 ≤ level ≤ 1, and −1 ≤ level ≤ 1 on modulation inputs, S5.21); it reads the sum of level × output over its pins, or its normalled source while it has none. Exactly one keys.pitch pin at 100 % on vcoN.pitch keeps the full-precision key pitch, and exactly one keys.gate pin at 100 % on envN.gate keeps key-event triggering, so they behave exactly like the normalled connection; any other mix is an ordinary signal (pitch 1.0 per octave, gate edges at 0.5). Global sources (lfo1, lfo2, noise, noise.rand) on out.in are added once, per-voice sources per voice. A VCO is computed when any pin (or the normalled source) of any input uses it, mixer inputs only with their level above 0. Text form, used by the saved state (property patch), patch files ([cables] input = pins) and 9P /cables: per input "out[@level]+out[@level]..." with the level as a fraction (0.5, .25) or percent (50%), omitted at 100 % (written with up to 4 significant digits), e.g. "vcf1.cutoff=env2.out@0.5+lfo1.out;out.in=vcf2.out". Older one-cable texts are valid as they are, so there is no state version change (an older LMW-Synth reading a text with levels or several outputs ignores all cables). An unknown output, a level outside 0 < l ≤ 1 (since Phase 25a: outside −1 … 1, or below 0 on an audio or gate input, S5.21), an output twice or a fifth pin makes the text invalid. The default sound is bit-identical.
S5.15 NOISE module (Phase 11, 2026-11-12). Noise has its own panel NOISE (before: only a socket on the MIXER panel) with Colour White / Pink / Brown (noise.colour [White]; pink −3 dB/octave with Paul Kellet's filter, brown −6 dB/octave with a leaky integrator, both on the same white generator; white is exactly the former noise, so the default sound is bit-identical) and a sample & hold random source: noise.rate 0.05–50 Hz [4] new uniform random values ±1 per second, noise.smooth 0–1 [0] glides towards each value (time constant Smooth / (3 × Rate)); output noise.rand (shared, own generator). Sockets: Out (noise.out, still normalled to mix.in4) under Colour, Rand under Smooth. Layout: row 1 VCO 1–3 | NOISE | LFO 1; LFO 2 moved to row 3 next to the VCA it feeds (KEYS | ENV 1 | ENV 2 | LFO 2 | VCA | OUT); the widest row has 15 columns, window 1276×884 (18 columns, 1496×884 since S5.16); the on-screen keyboard's keys widen to fill the window (16 px minimum, then it scrolls). A saved panel layout from before falls back to the default.
S5.16 FORMANT module (Phase 16a, user 2026-11-20): a vowel filter after VCF 2, before the VCA (normalled vcf2.out → formant.in, formant.out → vca.in), per voice. Five band-pass filters in parallel (state-variable filters, src/dsp/Formant.h), one per formant, each at the centre frequency, level and bandwidth of a sung vowel; data: the widely used table of sung-vowel formants (Csound manual, "Formant values") for bass, tenor, alto and soprano; baritone lies between bass and tenor (frequencies geometric mean, levels and bandwidths average); child is the soprano table raised by 15 % (an approximation). Controls: Vowel formant.vowel 0–4 [0] = A, E, I, O, U, continuous — between two vowels the formants glide (frequencies on a log scale, levels and bandwidths linearly); the value box shows "A", "E-I 40 %" (40 % of the way from E to I) and takes such a text, a vowel letter or the number. Voice formant.voice Bass / Baritone / Tenor / Alto / Soprano / Child [Tenor] (the GUI box shows Bass, Bari, Tenor, Alto, Sopr, Child). Reso formant.res 0–1 [50 %]: 50 % = the table's bandwidths, 100 % = half of them (sharper), 0 % = double. Mix formant.mix 0–1 [0]: dry/wet, glides over 20 ms; at 0 the input passes exactly and the filters do not run, so the default sound is bit-identical to before. Vowel input formant.vowel (no normalled source; voltage control, user 2026-11-20): vowel position = fader + 4 × input, clamped to A..U (1.0 = the whole A to U span); its amount is the cable's level (S5.14). Output level: a fixed make-up gain (×4) keeps a saw within −6 to +5 dB of its dry loudness for every voice and vowel. Coefficients are recomputed only when vowel, voice or resonance change, at most every 16 samples. Sockets: Vowel input under the Vowel fader, In and Out under Mix. Panel FORMANT at the end of row 2 (MIXER | VCF 1 | VCF 2 | FORMANT): the widest row has 18 columns, window 1496×884 (compact 1116×678). Module presets per voice and vowel (S7.5).
S5.17 VCF routing (Phase 16b, user 2026-11-20): vcf2.routing Serial / Parallel [Serial], a box under VCF 2's Slope and Type (no label; "Ser" / "Par" in compact view; hover text explains). Serial: as before (mix.out → vcf1.in, vcf1.out → vcf2.in, vcf2.out → formant.in), bit-identical. Parallel: mix.out is normalled to vcf2.in too, and formant.in gets vcf1.out and vcf2.out at 50 % each (their average, so two equal filters sound as loud as one; e.g. lowpass + highpass side by side). Only these two normalled sources change; a cable on vcf2.in or formant.in overrides them as on any input. VCF 2 at its open setting passes its input exactly, so Parallel with VCF 2 open gives half VCF 1 + half the dry mix. Hover texts, the Matrix (rings on both cells), the Schematic (two dashed lines into formant.in) and 9P /ports ("vcf1.out@0.5+vcf2.out@0.5 -> formant.in") follow the switch. The routing is a parameter (saved state, patch files, 9P /params/vcf2/routing), not part of the cable text.
S5.18 Pulse wave (Phase 16c, user 2026-11-20): a fifth VCO wave choice Pulse (vcoN.wave, after Triangle, so saved states keep their waves): a narrow pulse, high for 12.5 % of the cycle, band-limited edges (polyBLEP, as the square), DC removed and scaled to a peak of +1 (−1/7 … +1, mean 0), like an AC-coupled analogue pulse — quieter than the square, bright and nasal, a good source for FORMANT (S5.16).
S5.19 LFO rate inputs (Phase 16d, user 2026-11-20: a voltage-controlled LFO instead of a low-frequency VCO): inputs lfo1.rate and lfo2.rate (no normalled source): rate = Rate fader × 2^input (1.0 = one octave up, −1.0 down), clamped to 0.01–50 Hz (the fader itself stays 0.05–20 Hz); a NaN or infinite signal leaves the fader's rate. Unpatched — and after unplugging — the LFO runs exactly at the fader's rate (bit-identical default). The LFOs are shared (S5.6), so their inputs read shared sources (LFO 1/2, noise, rand) directly and per-voice sources (ENV 1/2, keys, VCOs, filters, …) from the voice of the newest note ("last note"; 0 before any note); values from the previous sample. Sockets: Rate input under the Rate fader, beside Out; in the Schematic the LFO triangles get an input.
S5.20 Phase modulation (Phase 16e, user 2026-11-21: FM option 1, as on DX synths): every VCO gets an input vcoN.pm (no normalled source) and a PM fader vcoN.pm 0–10 [0], the modulation index in radians for 1.0 at the input: the VCO's phase is shifted by index × input / 2π cycles. VCO 1–3 thus work as FM operators patched by cable (e.g. vco2.out → vco1.pm: VCO 2 modulates VCO 1; a VCO's own Out on its PM input gives feedback); a VCO computed later in the sample reads an earlier one's current value, an earlier one the later one's previous value (one sample). With the fader at 0, or nothing on the input, the VCO is bit-identical to before; a NaN or infinite input is ignored. Works on every wave, clearest with sines. The index is fixed per note in this step (no envelope control: that needs an Index input, FM option 2, Plan "later"). Panel: FM | PM | Tune | Wave/Oct (4 columns; row 1 is 17 columns, window unchanged); sockets FM | PM | Pitch | Out. Schematic: VCO triangles 12 × 14 (three inputs pitch, fm, pm). VCO presets set pm too (0 for the built-ins; own presets without pm leave it as it is).
S5.21 Inverted (bipolar) cable levels (Phase 25a, user 2026-11-24: "some inputs could benefit from inverted input (e.g. the inverted output of an ADSR on a filter freq, resonance or FM / PM modulation) ... audio signals don't need it but modulation inputs could use it; we can also use the CV signal then to influence loudness or modulation over the length of the keyboard"; user's choice: a bipolar level, 0 in the middle; plain negative everywhere; up to 100 %).
- Modulation inputs take a cable level from −100 % to +100 %: vco1–3.pitch, .fm, .pm, vcf1/vcf2.cutoff, .res, formant.vowel, vca.cv, vca.mod, lfo1.rate, lfo2.rate. A negative level subtracts: the input reads the sum of level × output as before (S5.14), so −100 % is the inverted source. No offset anywhere (user's choice "plain negative everywhere"): an inverted envelope on vca.cv gives silence where the envelope is up (the input is clamped at 0 as now); on vcf cutoff it closes the filter as the envelope rises; keys.pitch at a negative level on vca.mod or a cutoff makes low notes louder or brighter (keyboard scaling).
- Audio inputs (mix.in1–4, vcf1/vcf2.in, formant.in, vca.in, out.in, comb.in, delay.in, reverb.in, main.in) and the gate inputs (env1.gate, env2.gate) stay 0 to 100 %.
- A level of 0 keeps the cable (silent), so a fader can pass through 0 (proposed; until now 0 removed the cable). A cable is removed only by removing it (menu, drag away, Delete, the Matrix menu, an input's text without it).
- Text form (S5.14): "vcf1.cutoff=env2.out@-0.5", "@0" allowed; a negative level on an audio or gate input, or outside −1..1, makes the text invalid. An older LMW-Synth reading a text with "@-…" or "@0" ignores all cables (S5.14's rule); noted in Changes.md as a one-way step (patches saved by the new version with an inverted cable do not load their cables in 1.4.0).
- The special cases of S5.14 (one keys.pitch pin at 100 % keeps the full-precision pitch, one keys.gate pin at 100 % keeps key triggering) need exactly +100 %.
- As built (Phase 25a): VCA gain is clamp(Initial + vca.cv, 0, 1) as before, so with VCA Initial at 100 % an inverted envelope on vca.cv is loud at rest and dips while the envelope is up — the offset comes from Initial. Code: Patch::connect refuses a negative level on an audio or gate input; lmw::dsp::removePin (any level below −1) removes a pin, lmw::dsp::bipolar(), minLevel(); Patch::hasPin (a pin may be at 0). The GUI refuses with "Not possible: … is an audio or gate input"; 9P /cables with "not possible: vca.in is an audio or gate input: levels 0 to 100 %, only modulation inputs take a negative level". A cable moved (drag) from a modulation input to an audio input keeps its level, a negative one becomes 0. lmw-mcp set_cables and the AI guide (docs/ai/SoundDesign.md) describe the negative levels. Every fader whose range runs through 0 (the Matrix level slider on a modulation row, VCO Tune, VCF Env, COMB Feedback) fills from 0 to the thumb and has a 0 mark.

## S5a Parameters

S5.22 Velocity input and amount on the VCA (Plan L15 → Phase 26, user 2026-11-24: "keys velocity to vca is not shown in the matrix but is shown in the schematic and not in the synth view, needs a fader in synth probably"; user's choice: a fader and a socket). - Ticks: short marks left of the track at round values, so their spacing shows the curve — lin: 0, 25, 50, 75, 100 % of the range; ±: the ends, the centre (longer) and half way; log: 1-2-5 steps per decade in range (Cutoff 20, 50, 100, 200, 500, 1k, 2k, 5k, 10k Hz; Rate 0.05 … 20 Hz); curve: round times / depths (0.01, 0.1, 0.5, 1, 2, 5 s; FM 0.5, 1, 2, 5, 12 st). Black, 1 px, on white (21:1).
- Tag: a tiny text (black on white) under the fader name: "lin", "±", "log", "curve".
- Hover text (S6.1): a line "Scale: linear", "Scale: linear around 0", "Scale: logarithmic (half way = 600 Hz)", "Scale: curved, more travel at small values (half way = 0.5 s)", with the real half-way value.
- Over 9P /info (S10.10) and so in lmw-mcp, each float parameter reports scale lin | pm | log | curve (the last item of its object).
- As built: the kind follows from the parameter (skewed with unit Hz = log, other skewed = curve, a range through 0 = pm, else lin; Volume is lin in gain, its ticks read -inf / -6 / 0 dB; Vowel ticks A E I O U); ticks closer than 6 % of the travel are left out (the top and majors win), so at the skew of Cutoff 200 Hz is left out; the values are right of the track (9 px, normal view only), the ticks left of it; the tag is a line of its own under the name (11 px, compact 9 px), kept free on every fader so the tracks line up.

## S7 Persistence
S7.1 Save/load patches (parameters + cable connections + notes) to a file: "Load..." and "Save..." in the header, using JUCE's own file dialog (black on white, also inside a DAW) in Documents/LMW-Synth Patches. Format .lmwpatch, plain hand-editable text (src/app/PatchFile.h): header lines format = 1, state_version, name; [parameters] id = value (floats as the shortest text (up to 9 significant digits) that, written back, gives the same stored value — a value written within the range (on the step) reads back exactly as written: the value goes through the 0–1 range as a 32-bit float, so many texts store the same value (800 keeps 800.0001; 1234.5678 and 1234.5673 store the same), and the text last written over 9P or read from a loaded patch file is given back while it still stores the current value (else, e.g. after a change in the GUI or a clipped number, the shortest text); choices by name, integers; a '# value with unit' comment after each float); [cables] input = pins (the text form of S5.14, e.g. vcf1.cutoff = env2.out@0.5+lfo1.out); [schematic] block = x, y for every symbol, written only when the Schematic tab's symbols were moved (S6.7; a file without it opens with the default drawing);  [notes] the free text, verbatim to the end of the file (also lines starting with '#' or '['). Reading: '#' comments, blank lines, CRLF, unknown keys and unknown sections (from newer versions) are ignored; parameters missing from the file, or with an unreadable value, get their default (a patch is always complete); choices are matched as over 9P (S10.10); names from older versions are translated (StateMigration.h); a file without a format line, of a newer format, or with an unknown socket or an input twice in [cables] is refused with a message and nothing changes. The patch name is the file name; it shows in the header ("Patch: name"). The Save dialog offers the name without ".lmwpatch" (user 2026-11-24: "when the user saves a new preset is the extension default? if so why does the user have to see the extension?"); the extension is added on saving, a name with a dot keeps it ("Pad v1.2" → Pad v1.2.lmwpatch; before, ".2" was replaced), and because the dialog checks the name as typed, an existing file is asked about once more ("\"Untitled\" already exists. Replace it?"). Instrument and module presets and themes ask for a name only (no extension shown).

S7.4 Effects tab (Phase 9b, 2026-11-12). The notebook tabs are Synth (the module panels, cables, rack; formerly Panel) | Effects | Matrix | Schematic | Notes (Matrix added in Phase 10c, S6.8; Schematic in Phase 12, S6.7). The Effects tab holds fixed effect panels (not movable; sockets since S7.6), placed after everything on the Synth tab: out = synth output (after OUT's volume and soft limiter) → effects → host. First effect: REVERB, JUCE's Freeverb (juce::Reverb, part of JUCE, AGPLv3) with faders Mix (reverb.mix 0–1 [0]: output = dry × (1 − Mix) + reverb × Mix, smoothed over 20 ms), Size (reverb.size 0–1 [0.5], room size / decay), Damping (reverb.damping 0–1 [0.5], darker reflections when higher) and Width (reverb.width 0–1 [1], stereo width). The reverb gets the synth signal (mono, stereo on the output) and is stereo itself. While Mix is 0 it does not run at all, so the output is exactly the synth's (default sound unchanged); when Mix reaches 0 its tail is cleared. Buffers are allocated in prepareToPlay (RT-safe). The host is told about a tail (getTailLengthSeconds 10 s) only while Mix is above 0. The reverb parameters are saved with the state and patch files and served over 9P like all parameters (/params/reverb/mix etc.). The keyboard and the header stay on every tab; hidden controls take no Tab focus.
S7.6 COMB and patchable effects (Phase 16f, user 2026-11-21). The Effects tab panels are SYNTH | COMB | REVERB | MAIN (SYNTH | COMB | DELAY | REVERB | MAIN since S7.8), with sockets (no longer "no sockets"): SYNTH has the output out.out (the synth after OUT's volume and limiter), COMB and REVERB an input and an output (comb.in, comb.out under Mix; reverb.in, reverb.out under Mix), MAIN the input main.in (what is heard). Normalled: out.out → comb.in, comb.out → reverb.in, reverb.out → main.in (since S7.8 comb.out → delay.in, delay.out → reverb.in); cables change the order (e.g. out.out → reverb.in, reverb.out → comb.in, comb.out → main.in: the comb after the reverb) or feed one effect from several sources with levels (S5.14). Effect ports carry the summed stereo signal and form their own domain: they connect only to each other, synth ports only to synth ports — refused with a message in the GUI, left out of the socket menus, marked with a thin diagonal stroke in the Matrix and refused over 9P /cables ("not possible: …"). Processing (processor, per sample, audio thread): COMB, then REVERB, then main (COMB, DELAY, REVERB since S7.8); an input whose source comes later in that order reads that source's previous sample. A normalled input passes its source exactly, so with both Mix faders at 0 the output is bit-identical to before. COMB (src/dsp/Comb.h): a feedback comb per channel, y = x + Feedback × lowpass(y delayed by sampleRate / frequency samples), output × √(1 − Feedback²) so broadband sound keeps about its loudness; controls Freq comb.freq 20 Hz–5 kHz [440, skewed, half way 440 Hz], Key comb.key 0–1 [0] (the frequency follows the newest note, one octave per octave from C4, gliding over about 10 ms), Feedback comb.feedback −95…+95 % [50 %] (positive: resonances at every multiple of Freq, hollow; negative: at the odd multiples of Freq/2, clarinet-like), Damping comb.damping 0–1 [20 %] (lowpass in the loop), Mix comb.mix 0–1 [0] (0 = off: not run, the input passes exactly; smoothed 20 ms). ## S10 GUI / engine split
S10.1 Engine and GUI communicate over 9P2000; the engine is the 9P server and the single source of truth for state.
S10.2 The audio thread never performs socket I/O, locking or allocation; it exchanges data with the 9P thread through lock-free SPSC queues.
S10.3 The 9P2000 server is implemented in this project (C++20, no external 9P library).
S10.4 Transports: Unix domain socket (default, all 3 OSes; Windows 10+) and optional TCP.
S10.5 Each engine instance (standalone or each plugin instance) gets a unique socket path/port.
S10.6 Telemetry (meters, scope) is served as 9P files read repeatedly by the client; ZeroMQ deferred until measurements show a need.
S10.7 Plugin and standalone keep a built-in JUCE GUI; the external GUI is an additional 9P client.
S10.8 External GUI is written in Kukel (MIT), runs as a separate process, and lives in the Kukel project (not this repo); done (user 2026-11-21). Next external GUI (Plan Phase 20, user 2026-11-21): a Python 9P client in this repo, details to be specified.
S10.9 Engine exposes /source (URL of source code) to satisfy AGPLv3 §13 for remote users.
S10.10 File tree (Phase 6b): /source (r, repository URL); /version (r, 2026-11-18): "<version> <commit>" and a newline, e.g. "0.1.0 6747385" (S6.10); /params/<module>/<name> (rw) for every parameter, the dotted ID as path (vcf1.cutoff → params/vcf1/cutoff, voice.count → params/voice/count): reading gives the real value (floats as the shortest text (up to 9 significant digits) that, written back, gives the same stored value — a value written within the range (on the step) reads back exactly as written: the value goes through the 0–1 range as a 32-bit float, so many texts store the same value (800 keeps 800.0001; 1234.5678 and 1234.5673 store the same), and the text last written over 9P or read from a loaded patch file is given back while it still stores the current value (else, e.g. after a change in the GUI or a clipped number, the shortest text); choices by name, integers), writing accepts the same; a choice is matched by name (any case), by name without " dB" and a leading "+" ("24" → "24 dB", "1" → "+1"), by a unique prefix ("low" → "Lowpass"), or finally by index; out-of-range numbers are clipped; /cables (rw): reading lists "input=pins" lines for every patched input (S5.14, e.g. "vcf1.cutoff=env2.out@0.5+lfo1.out"), writing such a line sets all cables of that input, "input=" removes them, "clear" removes all; /patch (rw): reading gives the whole patch text (S7.1), writing replaces the patch (parameters, cables, notes and patch name) when the file is closed; /notes (rw): the Notes text (S7.2), replaced when the file is closed; /ports (r): one line per input "input  <normalled source> -> <input>" (source on the left, S6.1) and one per output "output <name>"; /info (r, Kukel request 2026-11-17): one JSON array describing every parameter in the synth's order, one object per line: id (as in /params), name, kind ("float", "int" or "choice") and default; ints and floats min and max; floats unit ("%" shows value × 100, "dB" 20·log10 value, "s", "Hz", "oct", "st" the value itself), centre where the range is skewed (setSkewForCentre), step where it has one, and scale (lin, pm, log or curve, S6.17, since Phase 24c); choices the list of names, default by name. Floats are written with a decimal point (20.0). Built from createLayout() at start, e.g. {"id": "vcf1.cutoff", "name": "VCF 1 Cutoff", "kind": "float", "min": 20.0, "max": 18000.0, "default": 18000.0, "unit": "Hz", "centre": 600.0, "scale": "log"}. /undo, /redo (w, Phase 23a, S6.14): writing anything takes back or redoes one step ("nothing to undo" / "nothing to redo"); /history (r): one line per step, oldest first, "> " before the step /undo would take back. Every write to /params/..., /cables and /patch is one step (named by the parameter, "cables", "patch"); /notes is not. /serial (r, 2026-11-17): a decimal number and a newline that goes up with every change to parameters (from any source, also host automation; once per change — JUCE's later copy of a value into the state tree is not counted again, fixed 2026-11-21), cables, the patch name, notes, the schematic layout and the rest of the saved state — a client polls these few bytes instead of /patch; it starts at 0 when the instance starts (it may go up more than once per change; playing notes does not change it). /keys (rw, 2026-11-17): writing lines "on <note> [velocity]" and "off <note>" (note 0–127, velocity 1–127, default 100, "on <note> 0" = off) plays the notes like the on-screen keyboard (also shown there); every line is checked first, an error is "bad key line: <line>"; applied at each write; reading gives nothing. The existing files, formats and error texts stay as they are (the Kukel client depends on them).
S10.11 Semantics: small control files (/params, /cables, /keys) apply every write at once (each write holds whole lines; a trailing newline is optional); /patch and /notes collect the writes and apply them on clunk (an error then comes back on the clunk). Reads see a snapshot taken at open. Errors are 9P Rerror strings, e.g. "file not found" (also for an unknown parameter path), "bad value", "permission denied", "bad cable line: …", "unknown input: …", "unknown output: …", "bad key line: …", a patch file error (S7.1), "busy" (S10.12). Directories are read-only; create, remove and wstat (except no-op/truncate) are refused. msize at most 65536; at most 256 fids per connection; at most 1 MiB collected per open file.
S10.12 Changes from 9P are applied on the message thread (the 9P thread waits for it, at most 5 s; then it answers "busy" — a change may still be applied afterwards); in a host that does not run the plugin's message thread — e.g. Ardour's headless Lua tool, where the thread (VST3 IRunLoop) runs on the GUI's main loop — every change answers "busy", so the audio thread stays lock- and allocation-free (S10.2) and the cable queue keeps a single producer.
S10.13 Endpoints (Phase 6b): each instance listens on a Unix socket <pid>-<n>.sock in a per-user directory with owner-only access (Linux $XDG_RUNTIME_DIR/lmw-synth or /tmp/lmw-synth-<uid>, macOS $TMPDIR/lmw-synth, Windows %TEMP%\lmw-synth); the socket file is 0600 and removed on close; the standalone app also removes its socket files at once on SIGTERM, SIGINT and SIGHUP and then quits normally, saving its state (a second signal ends it at once; a plugin leaves signals to its host); sockets of processes that no longer run are removed when an instance starts. TCP only when the config file has ninep_tcp = [host:]port (host default 127.0.0.1; if the port is taken the next of 32 is used) — 9P2000 has no authentication, so keep it local. The address is printed on stderr at start and shown as the hover text of the "LMW-Synth" title. At most 16 connections; a message larger than msize closes that connection. Float values are given as the shortest text that gives the same stored value (S10.10), so a written 1000 or 800 reads back as 1000 or 800.
S10.14 Tool: lmw9p (tools/lmw9p.cpp), a small 9P client: lmw9p [address] ls [dir] | cat <file> | write <file> [text...] (text from stdin when omitted) | bench <file> <rate/s> <seconds> <values...> (load test: latency median/p99/max and errors); without an address it uses the newest socket. Also in build-u24/. Any 9P2000 client works, e.g. plan9port: 9p -a unix!<socket> ls -l /.

## S11 AI assistant (MCP server, Phase 18)
S11.1 Purpose (user 2026-11-20/22): an AI assistant the user is already logged in to (Claude Code, Claude Desktop, Gemini CLI — no API key) sets up a sound from a description ("a male ooo voice", "a breathy flute with a slow vibrato"). The assistant does the thinking; LMW-Synth offers the tools. Language C++ (user 2026-11-22): the program ships in every download and needs nothing else installed.
S11.2 Program: lmw-mcp (tools/lmw-mcp.cpp), a Model Context Protocol server over stdio: JSON-RPC 2.0, one message per line on stdin/stdout, logging on stderr only. The assistant starts it; it talks 9P to a running LMW-Synth (S10) — local only, no network of its own. Pure C++ (src/mcp/: Json.h, the JSON reader/writer; Server.h, the protocol and tools, written against a small 9P interface so it is tested without a synth; src/ninep/Session.h, ClientSession: a 9P client session that reports errors as text and notices a lost connection; lmw9p keeps its own). Usage: lmw-mcp [address] — the 9P address as for lmw9p; without one the newest running synth is used, looked up again when it goes away; lmw-mcp --version. The guide and the tutorial are built in (cmake/GuideText.cmake, cmake/TutorialText.cmake).
S11.3 Protocol: initialize (answers the client's protocol version when it is one we know, else ours, 2025-06-18; capabilities tools and resources; serverInfo lmw-mcp with the LMW-Synth version; instructions: a short guide to read the sound-design resource first and to audition with play), notifications/initialized, ping, tools/list, tools/call, resources/list, resources/read. Unknown methods: error -32601; bad JSON: -32700. A tool's failure is a result with isError true and a plain-text reason (e.g. "no LMW-Synth is running: start it first"), so the assistant can explain or retry.
S11.4 Tools (names, what they do):
- list_synths: the running instances (address, version, patch name); select_synth {address}: use that one.
- describe_synth: every parameter with its range, unit, default and choices (/info), and every socket with its normal source (/ports).
- get_sound: the whole current sound as patch text (/patch: parameters, cables, notes).
- set_parameters {values: {id: value}}: several parameters at once (numbers in the parameter's unit, choices by name, as in patch files); answers what was set and every value that was refused, with the reason.
- set_cables {cables: ["input=output[@level]+...", ...], clear_first}: cables as in /cables (S5.14); clear_first removes all cables before.
- list_presets: the built-in instrument presets (S7.7) and module presets per module kind (S7.5).
- apply_instrument_preset {name}: a built-in instrument as in the header Presets menu — every parameter (missing ones at their default), its cables, the patch name; the notes and the schematic layout stay.
- apply_module_preset {module, name}: one module's preset (e.g. vcf1 "Oboe", formant "Bass O", delay "Ping-pong").
- play {notes, velocity, seconds}: plays MIDI notes (0–127) together for 0.1–10 s, so the assistant (and the user) can hear the result.
- name_sound {name, notes}: sets the patch name, and the notes when given.
- save_instrument_preset {name, overwrite}: saves the current sound as an own instrument preset (S7.7: Documents/LMW-Synth Presets/INSTRUMENT/<name>.lmwpatch; the file name rule of S7.5); refuses an existing file unless overwrite is true.
- undo {steps}: takes back the last change(s), as the synth's Undo (S6.14; Phase 23c): every parameter set, cable change, preset or patch is one step; steps 1-100, default 1; answers the history (/history). Not offered to the Assistant tab (it has its Undo last answer).
S11.5 Resources: lmw://guide/sound-design (docs/ai/SoundDesign.md, built in: the modules and what they do to the sound, normalled signal flow, recipes for instruments, voices and effects, the parameter ranges that matter) and lmw://guide/tutorial (docs/tutorial/Tutorial.md).
S11.6 Setup for the user (README "AI assistant"): Claude Code `claude mcp add lmw-synth -- <path>/lmw-mcp`; Claude Desktop and Gemini CLI: an mcpServers entry with command <path>/lmw-mcp. Every download has lmw-mcp next to lmw9p; the Windows installer installs lmw-mcp.exe with the optional "Command-line tools" component (with lmw9p); build-u24 has it too.
S11.7 Safety: lmw-mcp changes only the synth it is connected to (through the same 9P files as lmw9p) and writes only its own preset files; it reads no other files and opens no network connection.

S12.2 Inside the synth: the tools of S11.4 come from the same code (src/mcp/Server.h), behind an in-process Link (no socket, no 9P connection): it reads and writes the same files the 9P server serves (/params, /cables, /patch, /notes, /keys, /info, /ports, /version), on the message thread. list_synths and select_synth are left out (there is only this synth). The sound-design guide (S11.5) is the start of the system prompt; the tutorial is available through one more tool, read_tutorial. New pure C++ in src/assistant/: the request builder, the answer parser, the tool loop and the cost count, written against a small HTTP interface (send a POST, get status, headers and body) so it is tested with a fake service; the real one uses juce::URL over HTTPS on a background thread. One background thread runs a question's whole tool loop (src/app/AssistantSession: the in-process Link over NinePService::readFile/writeFile, which wait for the message thread like a 9P connection; HTTPS with juce::WebInputStream — WinINet, NSURLSession, libcurl on Linux, loaded lazily; Stop cancels the running request); the tab hears back on the message thread and never blocks the audio. For tests the environment variable LMW_ASSISTANT_URL replaces https://api.anthropic.com (a fake service).
S12.3 Claude request (Messages API, raw HTTPS, no SDK — there is none for C++): POST https://api.anthropic.com/v1/messages with headers x-api-key, anthropic-version 2026-10-21, content-type application/json; body: model (S12.6), max_tokens 16000, system (the guide, marked cache_control ephemeral so later requests read it from the cache), tools (name, description, input_schema from the server's tools/list), output_config.effort (default medium), messages. Thinking is left at the model's default (not sent). The server-side fallback for declined requests is on for Opus and Sonnet (beta header server-side-fallback-2026-07-01, fallbacks "default"); not for Haiku 5.5, which answers a request with "fallbacks" with 400 (found 2026-11-23: in 1.3.0 every question failed with Haiku chosen; fixed for the next version). Not streamed at first: an answer arrives whole; each tool call is shown when it runs.
S12.4 Tool loop: the reply's whole content is appended to the conversation; for stop_reason tool_use every tool_use block is run, in order, and all tool_result blocks go back in one user message (a failed tool: is_error true with the reason); then the next request. Ends at end_turn; max_tokens says "the answer was cut short"; refusal says "the model declined this request" with its category; pause_turn sends the conversation again. At most 20 requests per question (then: "stopped after 20 steps"). Stop (button) ends the loop after the running request; changes made so far stay (Undo, S12.5).
S12.5 The tab (black on white and the contrast setting, S6.2): the conversation (the musician's questions, the answers as plain text with simple lists, and a line per tool call: "set vcf1.cutoff 800 Hz", "applied preset Male voice (ooo)", "played C3 for 2 s"); an input box (Enter sends, Shift+Enter new line); Send / Stop; New conversation; Undo last answer (since Phase 23c, S6.14): each answer is one step of the synth's undo history, "Assistant: <the question, up to 40 characters>"; the button takes back the latest step while that is an answer (again for the one before), otherwise it says "the last change was not the Assistant's: use Menu > Undo". (Until 23c: a /patch snapshot per question.) save_instrument_preset asks the musician first (Save / Cancel; replacing an existing preset says so). A short help text when the conversation is empty, with three example questions. The tab button "Assistant" follows Notes in the header (standalone only); tool lines are grey #4A4A4A italic (8.9:1, AAA), the rest black; save confirmations are the usual black-on-white dialog without icon. Notes count from C4 = 60 like the on-screen keyboard.
S12.6 Settings (a dialog from the tab, also Menu > Assistant settings...): Provider (Claude; S12.10 later); API key (hidden text, Paste, Clear) with Test connection (GET https://api.anthropic.com/v1/models with the key: free; says "key works" or the reason); Model: Claude Opus 5.5 (claude-opus-5-5, best results), Claude Sonnet 5.5 (claude-sonnet-5-5, about half the price), Claude Haiku 5.5 (claude-haiku-5-5, cheapest, weaker at longer tasks; the default — user 2026-11-23: start with the cheapest; until 1.3.0 Opus; effort stays Medium), with their prices shown; Effort low / medium / high (default medium); Key storage (user 2026-11-22: both, the musician chooses): "System keychain" (Windows Credential Manager, macOS Keychain, Linux Secret Service through libsecret; greyed out when not available) or "Settings file" (config.ini key assistant_key, with the note "stored as plain text"; on Linux and macOS the file is made readable by the user only); without a stored key the environment variable ANTHROPIC_API_KEY is used when set. "How to get a key..." opens tutorial Lesson 12 (S7.9) as text in its own window (the notes stay): the Claude Console (https://platform.claude.com), credit, creating a key, then the settings. config.ini keys: assistant_key_store (keychain / file; unset = the keychain when there is one), assistant_key (only with file), assistant_model, assistant_effort, assistant_limit. OK applies all (with the keychain the key is stored there and removed from the file; with the file it is removed from the keychain, so it is never in two places); a keychain error keeps the dialog open and says to choose the file instead; Cancel changes nothing. The keychain code is src/app/KeyStore (libsecret loaded at run time on Linux: no build dependency). First use (user 2026-11-22: "we have to make that clearer for the first time user"): without a key the empty tab starts with "Before the first question: the assistant needs a Claude API key (a paid account at Anthropic, a few cents per question). Press Settings... below ..."; a question sent without a key keeps the question in the box, says what is needed and opens the settings window.
S12.7 Cost (user 2026-11-22: shown while it runs): after each request the usage fields (input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens) × the model's prices give the cost; shown per answer ("≈ $0.03") and for the session ("this session ≈ $0.41") under the input box. Prices per million tokens, built in and editable in the settings file (prices change): Opus 5.5 $4 in / $20 out / $0.20 cache read; Sonnet 5.5 $2 / $10 / $0.10; Haiku 5.5 $0.10 / $0.50 / $0.01; cache writes 1.25 × the input price. Haiku 5.5 has a second rate card: a request whose prompt (input + cache read + cache write tokens) is over 100K tokens costs 5 × ($0.50 / $2.50); a price_ line for Haiku keeps that rule. Spending limit per session (user 2026-11-22: default $2, set by the musician in the settings dialog and kept in config.ini as assistant_limit; 0 = none): when reached, the next question asks "This session has cost about $2.04 (limit $2.00). Go on?" (Go on / Cancel); Go on allows the same amount again before it asks next. Price lines in config.ini: price_<model> = input output cache-read [cache-write] (dollars per million tokens; cache write 1.25 × input when left out) replace or add to the built-in table.
S12.8 Privacy (user 2026-11-22): before the first question ever, a notice: the questions, the answers and the current sound (parameters, cables, patch name and notes) are sent to Anthropic to be answered; no audio, no other files; see Anthropic's privacy policy (link); Continue / Cancel (Cancel: nothing is sent, the question stays in the box); remembered in config.ini (assistant_notice_seen = true). Shown after the key check, so a musician without a key first gets the settings. The settings dialog repeats it ("Privacy: ...").
S12.9 Safety: the model acts only through the tools (it changes this synth's sound, plays notes, writes own instrument presets after the musician agrees); it reads no files and opens no other connections. The key is sent only to api.anthropic.com and never written to the patch, the presets, the state, the log or the screen (the field shows dots). Errors in plain words: 401 "the key was not accepted", 403 "this key may not use this model", 429 and 529 "busy, trying again" (waits retry-after, at most 2 retries), 5xx likewise, other 4xx the service's message, no connection "no internet connection (or blocked by a proxy)".
