# Spec — software-synth-LMW

Items marked (?) await user confirmation.

## S1 Purpose
S1.1 A polyphonic software synthesizer, inspired by AlsaModularSynth (modules + patch cables).
S1.2 Semi-modular: a default signal path is prewired ("normalled"); inserting a patch cable into an input overrides its default connection. Own design, inspired by the ARP 2600 concept (not a replica).

## S2 Platforms & language
S2.1 Runs on Linux, macOS and Windows from one codebase. Linux targets: Ubuntu 24.04 LTS and newer, and the latest Fedora release (currently 45). Linux binaries are built on the oldest supported distro so they also run on newer ones.
S2.2 C++20, CMake, JUCE 9.
S2.3 CI and other external build steps (GitHub Actions `uses:` etc.) are pinned to a full commit SHA with the version as a comment, using the latest workable version; any exception is documented with its reason.

## S3 Audio & MIDI
S3.1 Audio output via JUCE audio device layer (standalone) / host (plugin).
S3.2 Input: MIDI keyboard; computer keyboard as fallback in standalone. Computer-keyboard notes (keys a w s e d f t g y h u j k o l p ;, starting at C4) work whichever control has focus, except while typing into a value box.
S3.3 Sustain pedal (CC64): while down, released keys keep sounding; pedal up releases them. Re-striking a sustained note retriggers it (no doubling).
S3.4 Pitch bend: applies to all sounding and new voices; range ±2 semitones (fixed for now; may become a parameter).
S3.5 Mod wheel (CC1): adds vibrato — the FM depth becomes vco.fm + wheel × 1 semitone (the LFO always reaches vco.fm; changed 2026-11-08 so FM also works without a MIDI controller).

## S4 Polyphony
S4.1 Voice count configurable at runtime, range 1–32.
S4.2 When all voices are busy, a new note steals the oldest voice, preferring voices already in release over held ones.
S4.3 A note-on for a note that is already sounding retriggers that voice (no doubling).
S4.4 Stealing/retriggering keeps phase and envelope level continuous (no click).
S4.5 Lowering the voice count releases the excess voices (they ring out); parameter id voice.count, default 8.
S4.6 The summed output passes a soft limiter: unchanged below -6 dBFS, smooth (tanh) knee above, never above -0.04 dBFS — no hard clipping with many voices.

## S5 Modules (initial set)
S5.1 VCO, VCF, VCA, ADSR, LFO, Mixer, Noise, MIDI-in, Audio-out. VCF: 24 dB/oct lowpass ladder with resonance. LFO: one shared (global) LFO for all voices.
S5.2 Default normalled patch (confirmed 2026-11-07): MIDI→VCO pitch; VCO→Mixer→VCF→VCA→Out; Noise→Mixer (level 0); ENV1→VCA; ENV2→VCF cutoff; LFO→VCO pitch with depth set by the mod wheel (0 by default).
S5.3 Ports. Outputs: keys.pitch, keys.gate, keys.vel (S5.8), vco1.out, vco2.out, vco3.out (S5.10), noise.out, lfo.out, env1.out, env2.out, mix.out, vcf1.out, vcf2.out (S5.11), vca.out. Inputs, with their normalled source (written source → input): keys.pitch → vco1.pitch, vco2.pitch, vco3.pitch; lfo.out → vco1.fm, vco2.fm, vco3.fm; keys.gate → env1.gate; keys.gate → env2.gate; vco1.out → mix.in1; vco2.out → mix.in2; vco3.out → mix.in3; noise.out → mix.in4; mix.out → vcf1.in; env2.out → vcf1.cutoff; vcf1.out → vcf2.in; env2.out → vcf2.cutoff; vcf2.out → vca.in; env1.out → vca.cv; vca.out → out.in.
S5.4 Cables. A cable connects one output to one input; an output may feed several inputs; an input takes at most one cable. A cable replaces the input's normalled source (it does not add to it); removing it restores the normalled source. Input amounts (vco.fm, mixer levels, vcf.env) still apply to a patched signal. A cable from a module computed later in the same sample (feedback) reads that output's previous sample. Cable changes reach the audio thread through a lock-free queue (S10.2).
S5.5 Signal levels: audio ±1; envelopes 0..1; LFO ±1; noise white, uniform ±1. vco.fm: 1.0 in = (vco.fm + mod wheel × 1) semitones. vcf.cutoff: 1.0 in = vcf.env octaves. VCA gain = vca.initial + vca.cv, clamped to 0..1. out.in: per-voice signals are summed; a global source (lfo, noise) is output once.
S5.6 Shared (global) modules: LFO, Noise. Per voice: VCO, ENV1, ENV2, Mixer, VCF, VCA. When the sound no longer ends with ENV1 (out.in or vca.cv patched, or vca.initial > 0), voices that have played keep running after release (drone), as on a modular.
S5.7 VCF: 24 dB/oct lowpass ladder (zero-delay-feedback, 4 one-pole stages, tanh-limited feedback), resonance 0..1 (self-oscillates near 1); cutoff 20 Hz–18 kHz, smoothed 20 ms in the log domain.
S5.8 KEYS module (Phase 4 step 2b). On-screen keyboard, computer keys and MIDI are merged before voice allocation, so they form one per-voice source: the KEYS panel (formerly POLY: Voices fader plus sockets), first in row 2 next to the envelopes, 2 columns wide. Outputs, per voice: keys.pitch (1.0 = one octave, 0 = C4 / MIDI 60, pitch bend included), keys.gate (1 while the key is held or sustained by the pedal, else 0), keys.vel (note-on velocity 0..1). New inputs with their normalled source: keys.pitch → vco.pitch; keys.gate → env1.gate; keys.gate → env2.gate. vco.pitch sets the VCO pitch (C4 + 12 × input semitones); vco.fm still adds on top. An envelope gated by keys.gate (normalled or by cable) follows the key events, so a repeated note retriggers it; gated by any other signal it starts on a rising edge (crossing 0.5 upward) and releases on a falling one; when its gate returns to the keys while the key is up, it is released. A voice whose env1.gate comes from something other than keys.gate keeps running after its key is released (drone rule S5.6); vco.pitch does not need this, as the sound still ends with ENV1. The default patch produces bit-identical output to before. The VCA keeps multiplying by velocity. A separate MIDI module is out of scope until several MIDI inputs/channels exist.
S5.9 VCF modes (Phase 4b a). Each VCF has Slope 24 / 12 / 6 dB per octave and Type Low / High / Band / Notch (parameters vcf.slope, vcf.type; choice boxes stacked in a fourth VCF column), made by mixing the ladder's input after feedback y0 and its four stage outputs y1..y4 (as in the Oberheim Xpander), so cutoff, resonance and self-oscillation behave alike in every mode: LP = y1 / y2 / y4; HP = y0−y1 / y0−2y1+y2 / y0−4y1+6y2−4y3+y4; BP = 2(y1−y2) / 4(y2−2y3+y4) (gain 1 at the cutoff); Notch = 1 − BP (y0−2y1+2y2 / y0−4y2+8y3−4y4, zero at the cutoff). Bandpass and notch have no 6 dB form: 6 dB acts as 12 dB (stated in the Slope hover text). Default 24 dB lowpass: exactly the original signal path (default sound bit-identical). A mode change crossfades the mix over 20 ms (no click).
S5.10 VCO 1–3 (Phase 4b b). Three VCOs per voice, each with FM depth, Tune (−7..+7 semitones, 0.01 st steps), Wave and Octave (−2..+2, choice "Oct" stacked under Wave); sockets vcoN.fm, vcoN.pitch (inputs, under the FM and Tune faders) and vcoN.out. Normalled: keys.pitch → vcoN.pitch; lfo.out → vcoN.fm (the mod wheel adds to every VCO's FM depth); vco1.out → mix.in1; vco2.out → mix.in2; vco3.out → mix.in3; noise.out → mix.in4. Mixer levels VCO 1 (default 100 %), VCO 2, VCO 3 (0 %), Noise (0 %). A VCO is only computed when something uses it (a mixer input with level above 0, or any other input), so VCO 2 and 3 cost nothing by default. Names changed: vco.* → vco1.*, mix.vco → mix.vco1, the old noise input mix.in2 → mix.in4; the saved state gets "stateVersion" 2, and a state without it is translated on load (parameter IDs and cable names, StateMigration.h). The default sound is bit-identical. Default layout: three rows — VCO 1 | VCO 2 | VCO 3 | LFO | OUT; MIXER | VCF | VCA; KEYS | ENV 1 | ENV 2 (row height reduced so it fits: window 1026×884, compact 762×678).
S5.11 VCF 2 (Phase 4b c). A second VCF with the same controls (Cutoff, Reso, Env 2, Slope, Type) and sockets (In, Cut, Out), in series: vcf1.out → vcf2.in, vcf2.out → vca.in, env2.out → vcf2.cutoff. Ports and parameters vcf.* became vcf1.* (state version 3; older states translated on load, StateMigration.h). VCF 2 is always computed (its state stays current); it is open — its output exactly its input — while it is a 24 dB lowpass without resonance whose modulated cutoff is at the maximum (the default; positive Env 2 modulation keeps it open). Entering or leaving that state crossfades over 20 ms, after the 20 ms cutoff glide. The default sound is bit-identical. Layout: row 2 MIXER | VCF 1 | VCF 2; VCA moved to the end of row 3.

## S5a Parameters
S5a.1 Parameter IDs are dotted paths that map 1:1 to 9P files (default in brackets): voice.count 1–32 [8]; vcoN.wave Sine/Saw/Square/Triangle [Saw], vcoN.octave −2…+2 [0], vcoN.tune −7…+7 st [0], vcoN.fm 0–12 st [0] for N = 1..3 (S5.10); mix.vco1 0–1 [1]; mix.vco2, mix.vco3 0–1 [0]; mix.noise 0–1 [0]; vcfN.cutoff 20 Hz–18 kHz [18 kHz], vcfN.res 0–1 [0], vcfN.env −5…+5 oct [0], vcfN.slope 24/12/6 dB [24], vcfN.type Low/High/Band/Notch [Low] for N = 1..2 (S5.9, S5.11); vca.initial 0–1 [0]; env1.attack 0–5 s [10 ms]; env1.decay 0–5 s [200 ms]; env1.sustain 0–1 [0.7]; env1.release 0–10 s [300 ms]; env2.* same ranges [10 ms, 300 ms, 0, 300 ms]; lfo.rate 0.05–20 Hz [5]; lfo.wave Sine/Triangle/Saw/Square [Sine]; out.gain 0–1 [0.8]. With these defaults the sound equals Phase 2 (filter open, no noise, no vibrato). Phase-2 ids env.* were renamed env1.* (old saved state loses the envelope values).
S5a.2 MIDI events are applied sample-accurately within an audio block.
S5a.3 Parameter changes act on sounding notes: volume immediately (20 ms smoothing); attack/decay times change the running stage; release time is taken at key release; a sustain-level change on a held note glides over 20 ms (no click). Filter cutoff is smoothed (S5.7); other parameters apply at the next block.

## S6 User interface
S6.1 Simple GUI with vertical sliders (faders, no rotary knobs) grouped per module in three rows — VCO 1 | VCO 2 | VCO 3 | LFO | OUT, then MIXER | VCF 1 | VCF 2, then KEYS (Voices) | ENV 1 → VCA | ENV 2 → VCF | VCA (titles show the normalled destination). Hovering a fader for 2 s shows a text with the input it acts on, its current source (normalled or cable) and what it does (e.g. FM shows FM + mod wheel = depth now), each with a value box showing units (ms/s, %, dB), and patch points for cables. Values can be typed into the box; double-click on a fader resets it to its default. Every hover text and menu that names a connection writes it in signal-flow order, source on the left: "lfo.out → vco.fm (normalled)", "vco.out → mix.in1 (normalled)". A fader that sets an input's amount sits above that input's socket (VCO: FM fader left, above the FM input; Tune above the Pitch input; then Wave and Oct).
S6.2 Default white background, black text; all colour pairs >= 4.5:1 (WCAG AA). This covers every window, including the standalone title bar, its Options menu and the audio/MIDI settings dialog: they look identical to the main panel. Done with a custom standalone app (src/app/StandaloneApp.cpp, JUCE_USE_CUSTOM_PLUGIN_STANDALONE_APP) that installs the LMW look-and-feel as the default before the window exists: white title bar with black text and a line below it, window buttons as black glyphs (hover outline, pressed inverted) instead of JUCE's yellow/red, solid black menu separators (JUCE: 30 % opacity). In a plugin host the host owns the window frame. Top-level windows we open (file chooser, alerts) use the LMW look also in a DAW: while an LMW editor is open its look-and-feel is JUCE's default inside the plugin binary. JUCE's grey file-list details, file icons and 50 % disabled buttons are replaced: black (white when selected) rows with outline glyphs; disabled buttons keep full-contrast text and get a dashed outline.
S6.3 Contrast adjustable interactively and via config file: presets AA (4.5:1), AAA (7:1), Max (21:1) and a custom minimum ratio (4.5–21; contrast can only be raised above AA). Interactive: a "Contrast" choice box in the header (AA 4.5:1, AAA 7:1, Max 21:1, Custom n:1 — Custom asks for the ratio in a black-on-white dialog). Config file: config.ini in the user settings folder (Linux ~/.config/LMW-Synth/, Windows %APPDATA%\LMW-Synth\, macOS ~/Library/Application Support/LMW-Synth/), plain "key = value" lines: contrast = AA|AAA|Max|Custom, contrast_ratio = 4.5..21, compact = true|false; unknown keys and unreadable values are ignored; it is read when a window opens and written when the setting changes. Black and white are 21:1 at every setting; the design greys (pressed keys) are raised to the chosen ratio against their surroundings — darker on white keys, lighter on black keys, inverted at Max — with the note name in black or white, whichever contrasts more. Hover on keys is an outline (no grey tint); the keyboard's octave arrows are solid black (JUCE's default 40 % opacity was ~2.8:1). Every drawn pair is listed in Theme.h and tested for every preset.
S6.4 Compact view: a "Compact" toggle in the header switches to narrower columns, shorter faders, smaller labels and value boxes (window 762×678 instead of 1026×884 with the default three rows, including the standalone title bar). The choice is stored with the saved state and as the default for new windows in the config file (S6.3); a saved state wins.
S6.5 Rack layout: each module panel (POLY, VCO, MIXER, VCF, VCA, LFO, OUT, ENV 1, ENV 2) can be moved by dragging its title bar; a black drop marker (bar) shows where it will land — between panels in a row, or above/below all rows for a new row — and the other panels move aside. A row holds at most as many fader columns as the widest default row (12), so the window width never changes; there are at most 4 rows and empty rows disappear; the window height follows the number of rows. A drop that does not fit shows no marker and changes nothing; Escape cancels a drag. Without a mouse: Tab to a panel title (focus ring), then arrow keys move it (up/down: into the neighbouring row at the same position; if that row is full, into a new row of its own, or the rows swap when the panel is alone); Enter, Shift+F10 or right-click opens a menu (Move left/right/up/down, Reset layout). QWERTY note keys keep working while a title has focus. The layout is stored with the saved state (property uiLayout, e.g. "0,1,2,3,4,5,6;7,8"; an invalid stored layout falls back to the default) and later also in the config file; a "Reset layout" button restores the default. Cables (Phase 4 step 2) follow the panels. Floating/undocked module windows are out of scope.
S6.6 Patch points and cables: each module panel has a socket row at the bottom; an input sits under the fader that sets its amount, other sockets share the remaining columns — KEYS: Pitch | Gate, Vel (outputs); VCO 1–3: FM | Pitch | Out; MIXER: In 1 | In 2 | In 3 | In 4, Noise out (noise has no panel), Out; VCF 1, VCF 2: In | – | Cut(off) in | Out; VCA: In, CV, Out; LFO: – | Out; OUT: In; ENV 1, ENV 2: Gate in | – | – | Out. Labels shrink to fit narrow slots. Inputs are white sockets with a black ring (black centre when a cable is plugged in), outputs black with a white ring — told apart by shape, not colour. Drag from an output to an input (or the other way) to patch a cable; the target socket gets a ring while dragging; dropping on an input that already has a cable replaces it. Dragging from a plugged input picks up its cable: drop it on another input to move it, anywhere else to remove it. Escape cancels. Cables are drawn above the panels as black lines with a white edge that sag in the middle, and follow the panels (S6.5) and compact view (S6.4). Without a mouse: Tab to a socket; Enter, Shift+F10 or right-click opens a menu (input: Connect from ▸ outputs, Remove cable; output: Connect to ▸ inputs, ticked = cable, choose again to remove, Remove cables from here; both: Remove all cables); Delete removes an input's cable. Menus list only possible actions (no greyed items, S6.2). Hover texts show each input's source (normalled/cable) and what each output feeds. The cables are stored with the saved state as text (property patch, e.g. "vco.fm=env2.out;vcf.in=vcf.out", PatchText.h); an unreadable list means no cables. Normalled connections are not drawn (panel titles and hover texts show them).
S6.7 Schematic view (idea, not yet planned in detail; user request 2026-11-09). The current panel view becomes one tab of a notebook; a second tab shows the instrument as a stylized schematic with its connections (normalled and cables): VCO, VCF, VCA, LFO and MIX as triangles pointing right (signal flow left to right), ADSR probably as an ADSR curve in a rectangle; other symbols to be decided by the user.

## S7 Persistence
S7.1 Save/load patches (parameters + cable connections + notes) to a file: "Load..." and "Save..." in the header, using JUCE's own file dialog (black on white, also inside a DAW) in Documents/LMW-Synth Patches. Format .lmwpatch, plain hand-editable text (src/app/PatchFile.h): header lines format = 1, state_version, name; [parameters] id = value (floats with full precision so a reload is exact, choices by name, integers; a '# value with unit' comment after each float); [cables] input = output; [notes] the free text, verbatim to the end of the file (also lines starting with '#' or '['). Reading: '#' comments, blank lines, CRLF and unknown keys are ignored; parameters missing from the file get their default (a patch is always complete); names from older versions are translated (StateMigration.h); a file without a format line, of a newer format, or with an unknown socket or an input twice in [cables] is refused with a message and nothing changes. The patch name is the file name; it shows in the header ("Patch: name").
S7.2 Notes: a Notes tab next to Panel (the first notebook tab, S6.7) holds free-text notes for the patch, saved with the patch file and with the plugin/standalone state. While Notes is shown the panels, sockets and cables are hidden (also from Tab focus); the keyboard and the header stay. Typing in Notes does not play notes.
S7.3 The plugin/standalone state also keeps the notes and the patch name.

## S10 GUI / engine split
S10.1 Engine and GUI communicate over 9P2000; the engine is the 9P server and the single source of truth for state.
S10.2 The audio thread never performs socket I/O, locking or allocation; it exchanges data with the 9P thread through lock-free SPSC queues.
S10.3 The 9P2000 server is implemented in this project (C++20, no external 9P library).
S10.4 Transports: Unix domain socket (default, all 3 OSes; Windows 10+) and optional TCP.
S10.5 Each engine instance (standalone or each plugin instance) gets a unique socket path/port.
S10.6 Telemetry (meters, scope) is served as 9P files read repeatedly by the client; ZeroMQ deferred until measurements show a need.
S10.7 Plugin and standalone keep a built-in JUCE GUI; the external GUI is an additional 9P client.
S10.8 External GUI is written in Kukel (MIT), runs as a separate process, and lives in the Kukel project (not this repo).
S10.9 Engine exposes /source (URL of source code) to satisfy AGPLv3 §13 for remote users.
S10.10 File tree (Phase 6): /source (r, repository URL); /params/<module>/<name> (rw) for every parameter, the dotted ID as path (vcf1.cutoff → params/vcf1/cutoff, voice.count → params/voice/count): reading gives the real value (floats as exact numbers, choices by name, integers), writing accepts the same (a choice also by index), out-of-range values are clipped; /cables (rw): reading lists "input=output" lines for every cable, writing takes such lines, "input=" removes that cable, "clear" removes all; /patch (rw): reading gives the whole patch text (S7.1), writing replaces the patch when the file is closed; /notes (rw): the Notes text (S7.2), replaced when the file is closed; /ports (r): one line per input "input <- normalled source" and per output.
S10.11 Semantics: small control files (/params, /cables) apply every write at once (each write holds whole lines; a trailing newline is optional); /patch and /notes collect the writes and apply them on clunk (an error then comes back on the clunk). Reads see a snapshot taken at open. Errors are 9P Rerror strings ("unknown parameter", "bad value", "permission denied", "file not found", ...). Directories are read-only; create, remove and wstat (except no-op/truncate) are refused. msize at most 65536; at most 256 fids per connection; at most 1 MiB collected per open file.
S10.12 Changes from 9P are applied on the message thread (the 9P thread waits for it, with a time-out), so the audio thread stays lock- and allocation-free (S10.2) and the cable queue keeps a single producer.
